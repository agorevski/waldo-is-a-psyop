# Waldo Psyop Site

Build, one scene at a time, a static site that looks like it was made by hand at 3 a.m. by an obsessive conspiracy theorist. He has stared at a *Where's Waldo?* scene for 31 nights and concluded that **Waldo doesn't exist: he is a uniform, handed out in pieces** to the people in the picture. Each scene is a new **case file** by the same author. One shared engine renders every scene, and a gallery lists them.

## Inputs (ask for nothing else)

- **Scene image path** (required): JPEG, PNG, WebP, or anything Pillow can read.
- **Scene id** (optional): a slug matching `^[a-z0-9][a-z0-9-]{0,39}$`. If it's not given, derive it from the file name (`new_scene.py` does this: `waldo_beach.jpg` becomes `beach`). If the file name is meaningless (`IMG_1234`), name the scene after its content (`ski-slopes`, `fairground`).

Everything else (hooks, regions, all copy, crops, the manifest entry) is generated by you. Do not ask the user for copy or regions.

## Mode detection

Check the repo root first:

- **ADD A SCENE**: `scene.html`, `assets/js/scene.js`, and `scenes/index.json` all exist. Reuse the engine untouched. You (the orchestrator) produce only `scenes/<id>/**` and one `{"id": "<id>"}` entry in `scenes/index.json`. Go to the workflow below.
- **BOOTSTRAP**: the engine is absent (a new or empty repo). First do the workflow's Steps 1–5 for the scene (so `case.json` exists to build against), then build the engine with parallel builders (see "Bootstrap: build the engine"), then finish Steps 5–8.

If only part of the engine exists, treat it as BOOTSTRAP but keep the existing files that already pass `check_render_contract.py`.

## Two audiences, one page

- **The author** (in character everywhere except the footer) is sincere, sleep-deprived, and certain. He never hedges, never winks, and never explains the joke.
- **The reader** is a normal person. They should be able to confirm every factual statement in seconds, nod along, and then catch themselves thinking "…huh." The humour comes from the gap between true observations and the wrong conclusion.

This is parody. The footer disclaimer is the only place the site breaks character.

## The thesis, generalized

The thesis never changes: Waldo isn't a man; he's a uniform, handed out in pieces. The *evidence* changes with every scene and must come only from what is verifiably in that image: printed text, Waldo look-alikes, stripes, uniforms, odd objects. (In the beach case file, it was a stamp and a postmark.) Every scene must stand alone, with no fact, region, or asset from another image. While writing a scene (Step 3), the author may cite an earlier case file in passing, once or twice. Structured cross-scene connections (the grand theory, `crossLinks`, and the cross-referencing updates) are built only in Step 6, the three-layer refinement.

## The Plausibility Ladder (core rule, never relax it)

Every claim is built the same way:

1. **Fact 1**: something literally visible, with a source-pixel region. Checkable in about 5 seconds.
2. **Fact 2**: a second visible thing, also with a region, that sits next to Fact 1.
3. **The leap**: one wrong-but-tempting conclusion that uses only words, colours, positions, or objects that are actually in the image.

Rules:
- Facts must be true. If a detail can't be confirmed at zoom, it can't be a fact. The author may mention it only as something he *couldn't* find.
- Each leap is **one step** from the facts, not a random non-sequitur. Test: a normal reader can say what the author is thinking, even while disagreeing.
- Claims escalate and **cite earlier claims**. The site is one chain of reasoning, not a pile of trivia.
- Fewer, stronger claims beat many weak ones: **10–12 claims, exactly 2 facts each**.
- Every fact has a **SEE FOR YOURSELF** button that spotlights its region on the real image.
- The scene's **Dropped list** is binding: dropped items never appear as facts.

Persona, voice, and content safety rules (no hedging, no real people, no clinical or diagnostic language, obsessive not cruel) are in [references/voice.md](references/voice.md). Read it before writing any copy.

## File layout

```
index.html                  # gallery shell                    (engine: Builder B)
scene.html                  # scene shell, ?id=<id>            (engine: Builder B)
assets/css/styles.css       # all styling                      (engine: Builder B)
assets/js/scene.js          # scene renderer, scene-agnostic   (engine: Builder C)
assets/js/gallery.js        # gallery renderer                 (engine: Builder C)
scenes/index.json           # manifest + gallery copy + grand theory (orchestrator)
scenes/<id>/case.json       # ALL copy, regions, links         (orchestrator)
scenes/<id>/scene.<ext>     # the scene image                  (orchestrator)
scenes/<id>/evidence/*.png  # verified crops                   (orchestrator)
scenes/<id>/hooks.md        # verified hook table + Dropped    (orchestrator)
.waldo-work/                # scratch: survey tiles, zooms, contact sheets, theory/ layer notes (never commit)
```

Every URL is relative (the site is served from a GitHub Pages subpath). Paths inside `case.json` are relative to the scene folder.

## Workflow

Track these steps as a checklist. `S=.claude/skills/waldo-psyop-site/scripts`; run everything from the repo root.

### Step 1: Scaffold

```sh
python3 $S/new_scene.py path/to/image.jpg [--id <id>]
```

This validates and derives the id, refuses to overwrite an existing scene (use `--force` only to deliberately replace one), copies the image to `scenes/<id>/scene.<ext>`, writes a `case.json` skeleton with the real `image.width`/`height` and `TODO` placeholders, creates `evidence/`, and appends the id to `scenes/index.json` (creating the manifest if it is missing). `validate_case.py` rejects every `TODO`, so nothing ships unfinished.

### Step 2: Survey the image and verify hooks

```sh
python3 $S/survey.py scenes/<id>                 # overview (100 px grid) + ruled 3x tiles in .waldo-work/<id>/survey/
python3 $S/zoom.py scenes/<id> X Y W H           # 8x zoom, source-pixel rulers, region outlined in cyan
```

Follow [references/hook-discovery.md](references/hook-discovery.md) exactly. **View** the overview and every tile, list candidates, then confirm each one with `zoom.py` at 4–10× until the outline hugs the object. Name objects for what they are. Record the hook table, the lineup suspects, the census stripes, and the **Dropped list** in `scenes/<id>/hooks.md` (format: [references/examples/beach-hooks.md](references/examples/beach-hooks.md)). You need enough hooks for 10–12 claims, about 5 lineup suspects, and 10–20 census stripes.

### Step 3: Write `scenes/<id>/case.json` (orchestrator only)

- Follow [references/data-contract.md](references/data-contract.md) exactly, including `image.alt`, `site.censusInstructions`, and (if the scene has a clear complete Waldo image) `lineupReference`.
- Plan the claim chain first: sort hooks into the beats *issued*, *plural, in pieces*, and *managed*, then order an escalation arc (opening claim, middle claims that cite earlier ones, closing claims that set up the verdict). See [references/hook-discovery.md](references/hook-discovery.md#8-from-hooks-to-a-claim-chain).
- One voice writes ALL copy: claims, intro, banner, marquee, guestbook, updates, receipts, verdict, cipher (ROT13), and census comments. Regions come only from `hooks.md`. Use a new `caseNumber` and keep `hitCounterBase`, timestamps, and "Night 31" consistent with the persona.
- Asset paths are `evidence/<name>.png`. Run the copy review checklist in [references/voice.md](references/voice.md).
- Do not change `scenes/index.json` except for the scene entry (and the gallery copy only if the user asked).

### Step 4: Generate and visually verify crops

```sh
python3 $S/make_crops.py scenes/<id> --scale 6 --facts --sheet .waldo-work/<id>/crops-sheet.png
```

- `make_crops.py` cuts each claim's and lineup suspect's `region` to its `asset`. It skips existing files unless `--force` is given.
- **Open the contact sheet and look at every tile**, including each fact region. Each must show what its text describes. Fix wrong regions (re-check with `zoom.py`), then re-run with `--force`.
- A claim's asset may be a hand-made composite of verified regions (for example, every suspect side by side for the lineup claim). Build composites with Pillow from verified regions only. `validate_case.py` warns that a crop's "aspect differs from region aspect"; for an intentional composite, that warning is expected.

### Step 5: Validate

```sh
python3 $S/validate_case.py scenes/<id>          # must exit 0: no errors, no TODOs
python3 $S/validate_site.py                      # manifest + every scene + shells; CI runs this
```

Both must exit 0. Fix every error; review every warning. With two or more scenes, `validate_site.py` also fails until Step 6 has produced a theory that covers every scene. That failure is expected here; Step 6 resolves it.

### Step 6: Refine the grand theory (only when the manifest lists two or more scenes)

Skip this step with a single scene. Otherwise, follow [references/grand-theory.md](references/grand-theory.md) exactly. Re-run **all three layers, in order, over every listed scene**, never just the new one:

1. **Layer 1, Evidence inventory (facts only):** list every scene's claims and facts neutrally (one subagent per scene in parallel, if available). Group the things that verifiably recur across scenes, and re-view every cited fact on a contact sheet. Gate: at least 3 groups, each spanning two or more scenes, and every scene appears in at least one.
2. **Layer 2, Synthesis (the grand leap):** promote 3–6 groups to motifs, then write one thesis that explains them all, a 5–9-step escalating chain that cites every scene, and a 2–6-line verdict. Thread it back into the scenes with 1–4 `crossLinks` and one cross-referencing update per scene. Fix contradictions (case numbers, timeline, verdicts). Never change facts, regions, assets, or claim ids.
3. **Layer 3, Skeptic review (adversarial):** a fresh reviewer (a new subagent, if available) attacks the theory for truth, one-step leaps, escalation, coverage, consistency, standalone scenes, and voice. Fix or **cut** every BLOCKER and MAJOR finding; at most two rounds.

Record each layer's neutral summary in `theory.refinement` (layers 1, 2, 3). The theory lives in `scenes/index.json` (schema: [references/data-contract.md](references/data-contract.md)). Then re-run Step 5. Both validators must exit 0.

### Step 7: Preview

```sh
python3 -m http.server 8000
# http://localhost:8000/                    gallery: the new card appears, links to the scene
# http://localhost:8000/scene.html?id=<id>  the new case file
```

At 360 px and 1440 px: no console errors, no 404s, no horizontal scroll. Open every SEE FOR YOURSELF spotlight and confirm it shows what its fact describes. Check that other scenes still render, and that this scene's census, paranoia, and reset don't affect them. With a theory: the gallery shows the grand-theory section, each scene shows its theory link, and every evidence chip and cross-chip lands on the right claim. Then go through the Definition of Done.

### Step 8: Commit (and deploy)

Commit `scenes/<id>/**` and `scenes/index.json`, plus every other scene the refinement touched and the engine files when bootstrapping. Never commit `.waldo-work/`; delete it when you're done. If the repo has `.github/workflows/pages.yml`, a push to `main` validates and deploys; the scene goes live at `https://<owner>.github.io/<repo>/scene.html?id=<id>`.

## Bootstrap: build the engine (BOOTSTRAP mode only)

| Role | Owns | Notes |
|---|---|---|
| **Orchestrator** (writes and verifies) | `scenes/**` | Writes ALL copy in one voice. Generates and visually verifies every crop. `case.json` is finalised and valid before the builders start. |
| Builder B | `index.html`, `scene.html`, `assets/css/styles.css`, `README.md`, `.nojekyll` | Both shells and all styling for the render contract. Writes no narrative copy. |
| Builder C | `assets/js/scene.js`, `assets/js/gallery.js` | Renders everything from `case.json` and `scenes/index.json`. Scene-agnostic. Writes no narrative copy. |

- If subagents are available, run B and C as two parallel subagents. Give each one the full contents of [references/render-contract.md](references/render-contract.md), [references/design-and-interaction.md](references/design-and-interaction.md), and [references/data-contract.md](references/data-contract.md), plus its ownership row above. Otherwise, build B and then C yourself, keeping the same ownership boundaries.
- B and C work against the contracts, not against each other's files. If a builder needs a string that isn't in the JSON, it uses a neutral UI label (for example "Close" or "All case files"), never new in-character copy.
- The engine must work for ANY valid `case.json`: no claim ids, hooks, scene ids, or scene wording in the code. The image size, `viewBox`, and alt text come from `case.json`. `localStorage` keys use the prefix `wde-<id>-`.
- No external JS libraries. Web fonts (Anton, Special Elite, Comic Neue or Caveat) may be loaded with a stylesheet `<link>`. Add `<link rel="icon" href="data:,">`.
- Optionally add `.github/workflows/pages.yml`: install Pillow, run `validate_site.py --repo .`, then deploy `index.html scene.html assets scenes .nojekyll` to GitHub Pages on pushes to `main`.
- Verify with `python3 $S/check_render_contract.py` (scene.html) and `python3 $S/check_render_contract.py --gallery` (index.html), then Steps 5–7.

## Definition of Done

- [ ] `validate_case.py scenes/<id>` and `validate_site.py` exit 0. No `TODO` remains.
- [ ] `scenes/<id>/hooks.md` holds the verified hook table and its Dropped list. No dropped item appears as a fact.
- [ ] 10–12 claims, exactly 2 facts each, in an escalating chain where later claims cite earlier ones. About 5 lineup suspects and 10–20 census stripes.
- [ ] `python3 -m http.server` from the repo root serves the gallery and `scene.html?id=<id>` with no console errors or 404s at 360 px and 1440 px.
- [ ] Every fact's SEE FOR YOURSELF spotlight shows the thing the fact describes (the orchestrator checks this visually).
- [ ] Every crop matches its region. Every link, claim reference, and asset resolves.
- [ ] Census, paranoia, redactions, and board positions persist across reloads, per scene, and reset clears only the current scene.
- [ ] The author voice is consistent, in-character copy never hedges, and the footer disclaimer is present.
- [ ] No real people are named or targeted, no clinical or diagnostic language is used, and every fact is visible in the image.
- [ ] No horizontal scroll at 360 px. `prefers-reduced-motion` is respected. Every interactive element is keyboard reachable and has a visible focus style.
- [ ] Other scenes and the gallery still work.
- [ ] With two or more scenes: `theory` covers every listed scene, was produced by all three refinement layers (logged in `theory.refinement`), cites only existing verified facts, and has no open BLOCKER or MAJOR review findings. Every evidence chip and cross-chip resolves in the browser.
